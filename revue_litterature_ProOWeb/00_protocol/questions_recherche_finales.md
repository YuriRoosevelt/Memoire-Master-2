# Questions de recherche finales

## Question principale

**RQ0 : Quelles approches permettent de passer de modèles BPMN ou de modèles de processus métier vers des applications web ou des artefacts logiciels, et quelles limites justifient la conception d'un framework de génération comme ProOweb  ?**

## Questions secondaires

| ID | Question | Motivation |
|---|---|---|
| QR1 | Quel rôle BPMN joue-t-il dans la conception et l’automatisation des systèmes d’information orientés processus? | Comprendre le rôle de BPMN comme modèle métier et identifier ses limites lorsqu'il est utilisé seul. |
| QR2 | Quelles sont les capacités et limites des BPMS classiques pour construire des applications web métier complète et maitrisable? | Évaluer les BPMS comme solutions existantes et montrer leurs limites en matière de maîtrise, couplage et code source. |
| QR3 | Comment l’ingénierie dirigée par les modèles et la génération de code permettent-elles de transformer des modèles en artefacts logiciels? | Fonder scientifiquement la transformation des modèles en artefacts logiciels à travers le MDE et la génération de code. |
| QR4 | Comment les approches model-driven et low-code traitent-elles la génération, l'évolution et la maîtrise du code ? | Étudier la gestion du code généré, de son évolution et de sa maintenabilité. |
| QR5 | Comment les approches low-code, no-code et model-driven se rapprochent-elles ou se différencient-elles? | Clarifier les différences entre low-code, no-code et model-driven pour mieux positionner ProOWeb. |
| QR6 | Quelles lacunes restent ouvertes pour justifier une approche générative, modulaire et source-owned comme ProOWeb? | Identifier les lacunes globales justifiant une approche générative, modulaire et source-propriété. |

## Logique de progression

Les questions suivent une progression en entonnoir :

1. partir du concept général de système orienté processus ;
2. étudier BPMN comme langage de représentation ;
3. analyser les travaux de génération proches ;
4. comparer avec MDE, low-code et BPMS ;
5. identifier les besoins d'artefacts intermédiaires ;
6. dégager clairement la contribution de ProOWeb.
