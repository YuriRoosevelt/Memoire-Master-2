# Plan de rédaction du chapitre de revue de littérature

## 1. Introduction

Présenter le problème général : les applications web métier doivent souvent gérer des processus, et BPMN permet de représenter ces processus. Montrer immédiatement la limite : un diagramme BPMN ne suffit pas pour générer une application web complète.

## 2. Méthodologie de la revue

Décrire l'approche systématique qualitative :

- questions de recherche ;
- sources consultées ;
- requêtes ;
- critères d'inclusion et d'exclusion ;
- grille d'analyse.

## 3. Présentation du corpus

Présenter les 15 articles retenus par familles :

- PAIS et génération ;
- BPMN enrichi ;
- génération ou évaluation de BPMN par IA ;
- développement web dirigé par les modèles ;
- low-code et MDE ;
- workflows et données.

## 4. Analyse des travaux existants

Rédiger par axes, sans résumer article par article mécaniquement. Chaque axe doit expliquer :

- ce que les travaux apportent ;
- ce qu'ils ne couvrent pas complètement ;
- ce que ProOWeb peut en retenir.

## 5. Synthèse critique

Construire les lacunes :

- génération partielle ;
- dépendance aux moteurs ou plateformes ;
- faible maîtrise du code source ;
- manque de régénération sûre ;
- gestion limitée des personnalisations ;
- intégration incomplète entre processus, données, frontend et backend.

## 6. Positionnement de ProOWeb

Présenter ProOWeb comme une solution médiane :

- entre développement manuel et BPMS ;
- entre MDE et low-code ;
- entre modèle BPMN et application web source-owned.

## 7. Conclusion

Conclure que la littérature justifie une approche générative structurée reposant sur :

- BPMN enrichi ;
- contrats intermédiaires ;
- feature packs ;
- génération backend/frontend ;
- gouvernance des fichiers générés ;
- maintien de la maîtrise du code source.
